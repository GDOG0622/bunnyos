# BunnyOS 网页版与自部署版

同一套项目提供两种入口：

| | 网页版 | 自部署版 |
| --- | --- | --- |
| 使用方式 | 打开公开网址，无需安装 Node.js | 在自己的电脑或服务器运行 `npm start` |
| 主要存档 | 当前浏览器的 IndexedDB | 独立的 `BunnyOS-data/` 目录 |
| 访客隔离 | 不同浏览器各自保存；同一浏览器的同一入口共享一份存档 | 同一服务的登录者共享该部署的数据 |
| AI 请求 | 浏览器直接访问自己填写的 API，需要 HTTPS/CORS 支持 | Node.js 后端访问 API |
| 云端存储 | 手动上传/加载自己的 GitHub、Supabase 备份 | 同样支持手动云备份 |

## 构建公开网站

构建工具需要 Node.js 20.19+（推荐 Node.js 22）。

```bash
npm ci
npm run build:browser
```

将 **`dist/browser/` 目录里的内容**部署到任何支持 HTTPS 的静态托管。可以放在根路径，也可以放在 `/phone/` 等子路径；访问该目录的 `index.html` 启动。首次加载会安装当前入口的 Service Worker，并缓存网页资源。不能双击 `file://` 文件启动；本地预览可用 HTTP localhost 静态服务器。

### GitHub Pages

本项目公开入口为 <https://gdog0622.github.io/bunnyos/>。仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。工作流 `.github/workflows/browser-build.yml` 会在 `main` 更新后先运行测试，再将 `dist/browser/` 发布到 Pages；也可以在 Actions → Browser edition → Run workflow 手动运行。

Fork 项目时无需修改网址常量：网页版根据实际部署路径确定资源和存档位置。发布到新的网址后，浏览器视为新的存档位置；可通过导出/导入或个人云备份迁移。

使用 Node.js 自部署时，生成好的网站也会出现在 **`/play/`**，该入口无需私人站点的登录密码。原来的 `/` 仍是私人服务。不存在的 `/play/api/*` 请求会失败，不会回退到私人接口。公开构建仅复制程序资源和应用清单，排除用户数据、上传壁纸和图标、登录密码及线上环境配置。

## 访客使用

打开网页后，进入「设置 → 通用 API」填写自己的接口、密钥和模型。接口必须允许从网页来源发起的跨域请求；HTTPS 网站不能调用不安全的 HTTP 服务。公开网站不会提供或共享站长的 API Key。

角色、聊天、图片、世界书、预设、美化、钱包和 Suki 数据均保存在当前浏览器。清理站点数据、删除浏览器资料或使用会清理数据的隐私模式可能丢失存档。进入「设置 → 存储配置」申请持久存储，并定期导出完整备份或上传云端。申请结果由浏览器决定。

不同浏览器、设备、域名及网页版部署子路径使用独立存档。更换设备时先导出/上传备份，再在另一端导入/加载。云备份是手动快照，不会自动合并不同设备的修改；加载前会保留本机回滚快照。网页版和自部署版使用同一种可移植备份格式，可以互相迁移。备份包含设置中的 API Key，请保存在自己的私有空间。

## 浏览器能力边界

- HTTP / SSE MCP 可用，但服务必须允许浏览器跨域请求；stdio 本机命令只适用于自部署版。
- 提醒会在网页运行时检查；浏览器休眠、关闭所有页面后不保证后台执行，下次打开会检查到期提醒。浏览器关闭后继续生成和服务器 Web Push 需要自部署版。
- 图片上传到第三方图床、链接解析及远程内容获取受目标站点 CORS 限制。网页版不能代替服务器代理绕过限制，失败会显示错误或原有链接预览降级结果。
- 网页版 OpenAI 类模型使用本地 o200k_base 编码计数，其他模型使用字节估算，界面返回的 tokenizer 状态会说明精确性。模型上下文应预留余量。
- 首次加载后可离线查看、编辑本机存档；AI、云备份、外部字体和远程图片仍需要联网。

## 更新与验证

重新构建并替换静态资源即可发布更新。为避免中断生成或写入，新 Service Worker 会等旧页面关闭后接管；更新后关闭该入口的所有页面再重新打开。更新只替换网页资源，不删除 IndexedDB 存档。

```bash
npm test
npm run build:browser
npx playwright install chromium
npm run test:browser
```

浏览器集成测试使用两个独立访客上下文，覆盖访客隔离、保存与刷新、同一浏览器多标签页、AI 回复落盘、备份导出/恢复、防止访问私人服务及离线启动。不会使用实际 AI 密钥或用户存档。

## 实现位置

`browser/worker.js` 在 Service Worker 中运行同一套 API 与业务模块；`browser/fs.js` 将文件读写映射到 IndexedDB，只有事务完成才确认保存。所有标签页共用一个活动 Worker，聊天和设置的版本冲突保护沿用原有实现。`browser/router.js` 适配原有路由，`browser/client.js` 负责入口隔离、存储状态和备份入口。`scripts/build-browser.js` 生成独立的静态发布包。
